## 5. Spatial & Map Telemetry Conventions

> [!IMPORTANT]
> **Coordinate Conventions**:
> 1. In individual field payloads and query parameters:
>    - `latitude`: Float between `-90.0` and `90.0`
>    - `longitude`: Float between `-180.0` and `180.0`
> 2. In GeoJSON format (`coordinates` array):
>    - Always formatted as `[longitude, latitude]` following RFC 7946 (e.g. `[77.7410, 12.9680]`).
>    - Directly compatible with Mapbox GL, MapLibre, Leaflet, or Deck.gl layers.

### Vehicle Status Lifecycle
- `AVAILABLE`: Vehicle is ready for route dispatch; has unallocated cargo capacity.
- `IDLE`: Vehicle is parked/waiting at a depot or hub without an active trip.
- `IN_TRANSIT`: Vehicle is actively driving on a route.
- `BREAKDOWN`: Mechanical failure or roadside emergency; immediate attention required.
- `MAINTENANCE`: Vehicle undergoing scheduled service or repairs in depot.
- `OFFLINE`: Vehicle decommissioned, deregistered, or marked `is_active: false`.

## 8. Order Management System APIs

### A. Order Lifecycle State Machine
```
   CREATED
      │
      ├──> CANCELLED (terminal)
      ▼
  CONFIRMED
      │
      ├──> ON_HOLD ──> CONFIRMED / PROCESSING / CANCELLED
      │       ▲
      ▼       │
  PROCESSING ─┤
      │       │
      ▼       │
 READY_FOR_DISPATCH
      │
      ▼
  DISPATCHED
      │
      ├──> FAILED_DELIVERY ──> PROCESSING / ON_HOLD / CANCELLED
      ▼
  IN_TRANSIT
      │
      ├──> DELIVERED (terminal)
      └──> FAILED_DELIVERY
```

> [!IMPORTANT]
> **State Machine Invariants**:
> - Direct transition from `CREATED` or `CONFIRMED` to `DELIVERED` is strictly forbidden (`400 Bad Request`).
> - When an order transitions to `DELIVERED` or `CANCELLED`, its assigned vehicle's `current_load_kg` is automatically decremented.
> - Vehicle assignment validates active status, non-maintenance status, and remaining capacity (`capacity_kg - current_load_kg >= order.total_weight_kg`).

## 10. Network Visualization & Graph Intelligence APIs

Stage 7 transforms the underlying database into a graph engine powered by NetworkX. It computes Dijkstra shortest paths, topological validations, graph analytics, degree distributions, and standard RFC 7946 GeoJSON FeatureCollections for map visualization.

### A. Endpoints Overview

| Method | Endpoint | Description | Permissions |
|---|---|---|---|
| `GET` | `/api/v1/network/graph` | Full graph topology, nodes, edges, density, connectivity | All authenticated roles |
| `GET` | `/api/v1/network/analytics` | Graph metrics (degree, density, components, total/avg distances) | All authenticated roles |
| `GET` | `/api/v1/network/validate` | Topology audit (isolated nodes, missing refs, coordinate checks) | All authenticated roles |
| `GET` | `/api/v1/network/geojson` | RFC 7946 GeoJSON FeatureCollection (`all`, `nodes`, `edges`) | All authenticated roles |
| `GET` | `/api/v1/network/shortest-path` | Dijkstra shortest path (`distance` or `travel_time`) | All authenticated roles |
| `GET` | `/api/v1/network/nodes/{id}/connections` | Incident edges, adjacent nodes, in/out degree | All authenticated roles |
| `GET` | `/api/v1/network/components` | Connected components and node memberships | All authenticated roles |

## 13. Disruption Management & Impact Analysis (Stage 9 Update)

LOGIPULSE Stage 9 introduces deterministic disruption management for vehicles, routes, warehouses, and orders.

### Disruption Types
- `VEHICLE_BREAKDOWN`: Engine/tire failures, stalls. Marks simulation vehicles as `BREAKDOWN`. Real fleet is isolated.

## 14. Multi-Agent AI Intelligence (Stage 10 Update)

Stage 10 introduces a controlled, explainable multi-agent AI system that evaluates operational data, coordinates specialist agents, and produces evidence-backed recovery recommendations.

> [!IMPORTANT]
> **Stage 10 Boundary Rule**: Recommendations are advisory only (`RECOMMENDED_ONLY`). They are NOT automatically executed on production fleet, warehouses, or orders (automatic execution belongs to Stage 11).

### Specialist Agents
1. **Coordinator Agent**: Receives request, coordinates specialists, detects operational conflicts (e.g. vehicle recommended vs. corridor impassable), and synthesizes executive recovery strategy.
2. **Disruption Analysis Agent**: Assesses severity, criticality drivers, and downstream operational blast radius using Stage 9 Disruption & Impact models.
3. **Fleet Intelligence Agent**: Evaluates available vehicles (`AVAILABLE`, `IDLE`) with adequate capacity_kg. Strictly excludes vehicles in `BREAKDOWN`, `MAINTENANCE`, or `OFFLINE`.
4. **Routing Intelligence Agent**: Utilizes Stage 7 NetworkX graph service and Dijkstra shortest-path to evaluate route detours and delta distance/time.
5. **Warehouse Intelligence Agent**: Evaluates storage headroom, flags hubs $>80\%$ utilized, and checks inventory feasibility.
6. **Order Priority Agent**: Evaluates customer orders, ranks delivery queue by urgency (`URGENT` / overdue first), and identifies SLA breach risks.

### LLM Architecture & Dual Provider Fallback
- Primary Provider: Google Gemini (`gemini-1.5-flash`)
- Fallback Provider: Groq Cloud (`llama-3.3-70b-versatile`)
- If both providers fail or keys are unconfigured, a deterministic rule-based analysis is generated without crashing.

### Key Agent APIs
- `POST /api/v1/agents/analyze/{disruption_id}`: Trigger multi-agent analysis run (`OPERATIONS_MANAGER`, `FLEET_MANAGER`, `WAREHOUSE_MANAGER`, `ADMIN`).
- `GET /api/v1/agents/runs`: List paginated agent runs.
- `GET /api/v1/agents/runs/{run_id}`: Full intelligence report with execution breakdown and synthesized recommendations.
- `GET /api/v1/agents/runs/{run_id}/executions`: Granular execution logs per specialist agent.
- `GET /api/v1/agents/runs/{run_id}/recommendations`: Prioritized recovery recommendations with validation status (`VALIDATED`, `REQUIRES_VALIDATION`, `REJECTED`, `INFORMATIONAL`).
- `GET /api/v1/agents/status`: Provider availability status (safe: keys are not exposed).
- `POST /api/v1/agents/runs/{run_id}/retry`: Re-trigger analysis for an existing run.

### WebSocket Stream Integration
When disruptions belong to an active simulation, events are broadcast via `ws://localhost:8000/api/v1/simulations/{id}/ws`:
- `AGENT_RUN_STARTED`
- `AGENT_EXECUTION_STARTED`

## 15. Intelligent Optimization & Recovery Engine (Stage 11 Update)

Stage 11 translates Stage 9 disruptions and Stage 10 AI recommendations into mathematically optimal, constraint-verified logistics recovery plans.

> [!IMPORTANT]
> **Human Approval Rule**: All recovery plans are initially generated in `PENDING_APPROVAL` status. They CANNOT be executed without explicit human approval (`POST /api/v1/recovery/plans/{id}/approve`). Automated execution without approval is strictly prohibited.

### Mathematical Optimization Core
- **Engine**: Google OR-Tools (MILP / CBC solver with SCIP/GLOP fallbacks)
- **Routing**: NetworkX Dijkstra shortest-path detour computation
- **Constraints Enforced**:
  - Exact payload vs. vehicle remaining capacity headroom (`capacity_kg - current_load_kg`)
  - Strict exclusion of non-operational vehicles (`BREAKDOWN`, `MAINTENANCE`, `OFFLINE`)
  - Terminal order protection (delivering or cancelled orders cannot be reassigned)
  - Priority-weighted delay and travel cost penalties (`URGENT` > `HIGH` > `NORMAL` > `LOW`)

### Plan Status Lifecycle
```
[GENERATE] ──> PENDING_APPROVAL ──┬──> [APPROVE] ──> APPROVED ──> [EXECUTE] ──> EXECUTED
                                  │                                  │
                                  ├──> [REJECT]  ──> REJECTED        └──> (Failure) ──> FAILED
                                  │
                                  └──> (Pre-val fails) ──> VALIDATION_FAILED
```

### Simulation vs. Operational Isolation
- **Simulation-Scoped Plans** (`simulation_id` present):
  - Execution updates only `SimulationVehicleState` in the digital twin.
  - Production tables (`vehicles.status`, `vehicles.current_load_kg`, `orders.assigned_vehicle_id`) remain untouched.
- **Operational Plans** (`simulation_id` null):
  - Execution updates live database tables in an atomic transaction with full rollback on error.
  - Maintains immutable `RecoveryAction` and `RecoveryAuditLog` entries.

## 16. Analytics, Performance Monitoring & PDF Reporting (Stage 12 Final Backend Stage)

Stage 12 completes the LOGIPULSE backend by aggregating persisted records from Stages 0–11 into a unified analytics, trend monitoring, before-vs-after recovery comparison, and ReportLab PDF export engine.

### A. Data Integrity & Metric Classifications
All analytics endpoints return a `metric_classifications` dictionary and `unavailable_metrics` list:
- `ACTUAL`: Computed directly from persisted operational database records (`orders`, `vehicles`, `warehouses`, `inventory_items`, `inventory_movements`, `disruptions`, `agent_runs`, `recovery_plans`).
- `ESTIMATED`: Computed from deterministic impact or optimization models (`DisruptionImpact.estimated_delay_minutes`, `RecoveryPlan.estimated_total_delay_minutes`, `RecoveryComparison`).
- `SIMULATED`: Computed from digital twin tables (`simulations`, `simulation_vehicle_states`, `simulation_telemetry`) or records scoped to a `simulation_id`.
- `UNAVAILABLE`: Returned as `null` when underlying observations do not exist (e.g., `average_delivery_duration_minutes` when no delivered orders exist, `total_distance_travelled_km` when fewer than 2 telemetry points exist, `token_usage_total` and `estimated_llm_cost_usd` which are not persisted in `AgentExecution`).

### B. Mathematical Formulas & Denominators
1. **Delivery Success Rate (%)**:
   $$\text{Delivery Success Rate} = \frac{\text{Delivered Orders}}{\text{Total Orders} - \text{Cancelled Orders}} \times 100$$
2. **On-Time Delivery Rate (%)**:
   $$\text{On-Time Delivery Rate} = \frac{\text{Delivered Orders where } \text{delivered\_at} \le \text{expected\_delivery\_at}}{\text{Delivered Orders}} \times 100$$
3. **Overdue Orders vs Estimated Delayed Orders**:
   - `overdue_orders` (`ACTUAL`): Non-delivered, non-cancelled orders where `expected_delivery_at < current_utc_time`.
   - `estimated_delayed_orders` (`ESTIMATED`): Distinct orders with `DisruptionImpact.estimated_delay_minutes > 0`.
4. **Fleet Capacity Utilization (%)**:
   $$\text{Fleet Capacity Utilization} = \frac{\sum \text{current\_load\_kg}}{\sum \text{capacity\_kg}} \times 100$$
5. **Warehouse Storage Utilization (%)**:
   $$\text{Overall Warehouse Utilization} = \frac{\sum \text{used\_capacity}}{\sum \text{total\_capacity}} \times 100$$
6. **Agent Execution Success Rate (%)**:
   $$\text{Agent Success Rate} = \frac{\text{Completed AgentExecutions}}{\text{Total AgentExecutions}} \times 100$$
7. **Recovery Plan Success Rate (%)**:
   $$\text{Recovery Success Rate} = \frac{\text{Executed RecoveryPlans}}{\text{Total RecoveryPlans}} \times 100$$
   *(Note: `total_recovered_orders` counts only orders from `EXECUTED` or `PARTIALLY_EXECUTED` recovery plans; unexecuted plans are reported separately under `total_reassigned_orders_proposed`).*

### D. PDF Reporting Engine & Endpoints (`/api/v1/reports/*`)

Generated PDFs use **ReportLab** (`reportlab==5.1.0`) with numbered page footers (`Page X of Y`), executive summary tables, vector bar charts, and data limitation notes. Files are stored in `backend/generated_reports/` with strict filename sanitization and path traversal protection.

#### Supported Report Types (`GET /api/v1/reports/types`):
1. `EXECUTIVE_SUMMARY`
2. `FLEET_PERFORMANCE`
3. `WAREHOUSE_PERFORMANCE`
4. `DISRUPTION_REPORT`
5. `AI_INTELLIGENCE_REPORT`
6. `RECOVERY_PERFORMANCE`
7. `SIMULATION_REPORT`

| Method | Endpoint | Allowed Roles | Description |
|---|---|---|---|
| `POST` | `/api/v1/reports/generate` | `ADMIN`, `OPERATIONS_MANAGER`, `ANALYST` | Generate a PDF report and persist `ReportMetadata` (`201 Created`) |
| `GET` | `/api/v1/reports` | `ADMIN`, `OPERATIONS_MANAGER`, `ANALYST` | Paginated list of generated report metadata records |
| `GET` | `/api/v1/reports/types` | `ADMIN`, `OPERATIONS_MANAGER`, `ANALYST` | List all 7 supported report types and their sections |
| `GET` | `/api/v1/reports/{report_id}` | `ADMIN`, `OPERATIONS_MANAGER`, `ANALYST` | Inspect metadata and summary metrics for a report |
| `GET` | `/api/v1/reports/{report_id}/download` | `ADMIN`, `OPERATIONS_MANAGER`, `ANALYST` | Download binary PDF (`application/pdf`) |
